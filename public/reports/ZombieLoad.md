# ZombieLoad 实验报告
本项目具体说明

ZombieLoad (CVE-2018-12130) 展示了 Intel 处理器在微架构设计上的数据泄露风险。本项目复现了其中的 **Variant 3 (Windows)**，利用微架构数据采样（MDS）技术，证明一个非特权的用户态进程可以推测性地读取同一物理核心上另一个逻辑线程正在处理的数据。该攻击通过诱导处理器在发生异常或微码辅助（Microcode Assist）时，错误地将内部填充缓冲区（Fill Buffer）中的陈旧数据提供给预测执行路径，从而实现跨进程的数据窃取。

## 涉及资源

- **Fill Buffer (填充缓冲区)**
  
  - **位置**: CPU 内部（非架构可见缓冲区）。
    
  - **功能**: 在高速缓存未命中（Cache Miss）时，用于暂存从内存或 L3 缓存取回的数据块。
    
  - **利用**: 当处理器发生特定的架构异常（如访问未映射内存）时，流水线不会立即停止，而是会错误地使用填充缓冲区中的数据继续推测执行。
    
- **Cache (CPU 缓存 / L1D)**
  
  - **位置**: CPU 一级数据缓存。
    
  - **功能**: 快速数据存储。
    
  - **利用**: 攻击者通过 `Flush+Reload` 技术，利用缓存访问的时间差异作为隐蔽信道（Covert Channel），将填充缓冲区中的数据编码为缓存状态。
    
- **Intel TSX (Transactional Synchronization Extensions)**
  
  - **注**: 虽 Variant 3 在 Windows 上不强制要求 TSX，但在其他变体中常用于抑制异常导致的崩溃。
- **Hyper-Threading (超线程)**
  
  - **功能**: 允许两个逻辑核心共享同一组物理资源（如填充缓冲区）。
    
  - **利用**: 攻击成功的关键前提。受害者逻辑核将数据加载进物理核共享的缓冲区，攻击者逻辑核从该缓冲区中采样数据。
    

## 攻击原理

**时间差异产生原理**:

1. **注入与泄露**: 受害者不断加载字符（如 'K'）。由于超线程共享资源，'K' 的数据会经过物理核心的填充缓冲区。
  
2. **采样**: 攻击者故意触发一个异常访问。在异常处理前，CPU 处于“盲视”状态，会从填充缓冲区抓取最近的一个值（可能是受害者的 'K'）继续执行后续指令。
  
3. **编码与解码**: 攻击者利用这个抓到的值作为索引访问数组。随后通过测量数组每个位置的访问耗时，耗时最短（Cache Hit）的索引即为泄露的字符。
  

## 项目核心代码文件

- **`attacker/variant3_windows/main.c`**: 攻击核心程序，负责触发异常访问、执行 `Flush+Reload` 测量以及维护泄露数据的直方图。
  
- **`attacker/variant3_windows/cacheutils_win.h`**: 提供底层计时（`rdtscp`）和缓存刷新（`clflush`）的 Windows 适配函数。
  
- **`victim/windows/secret.c`**: 受害者程序，模拟处理机密数据，通过循环不断从内存加载特定字符以填充硬件缓冲区。
  
- **`attacker/variant3_windows/make.bat`**: Windows 专用编译脚本。

## 实验过程

- **编译程序**:
  
  在 `attacker/variant3_windows` 目录执行 `.\make.bat` 生成 `leak.exe`。
  
  在 `victim/userspace_linux_windows` 目录编译生成 `secret.exe`。
  
- **启动攻击者 (Attacker)**:
  
  打开管理员权限 CMD，绑定至 CPU 0：
  
  `start /affinity 1 leak.exe`
  
- **启动受害者 (Victim)**:
  
  打开另一个管理员权限 CMD，绑定至 CPU 1（同一物理核）：
  
  `start /affinity 2 secret.exe K`
  
- **观察实验**: 保持后台低负载，观察 `leak.exe` 的直方图输出。

## 实测结果

本次记录对应的目标 CPU 为 Intel Core i5-1235U。硬件检测结果明确表明该平台属于 MDS_NO 路径，意味着原始 ZombieLoad 的泄露链路会被显著抑制。最终观测到的直方图并未在秘密字符上形成稳定峰值，而是表现为大面积噪声，说明攻击在该平台上无法形成可靠解码。

## 运行时间

本次采用固定 500 ms 采样窗口统计输出，窗口内共识别到 **13 个完整直方图块**，据此折算得到平均每个完整直方图块约 **38.46 ms**。

测量过程使用 Windows PowerShell 脚本，从 attacker 进程启动后开始计时，先运行固定采样窗口，再统计标准输出中符合直方图格式 `[A-Z]: (   count)` 的连续 26 行块。

## 结论

ZombieLoad 的原始采样路径在第 12 代 Intel 平台上基本被硬件防御切断，实验更像是对防御效果的验证而不是有效的信息恢复。对该 CPU 而言，输出噪声大于泄露信号。
